# Интерфейс консультанта EKT

Адаптивный клиент API v1 для кейса №1: чат, карточки товаров и аналогов, характеристики и сертификаты, вложения, предложение количества, отдельное подтверждение/отмена и сессионная демонстрационная корзина `/cart`.

## Запуск

Требования: Node.js 22.12+ либо поддерживаемая более новая версия, npm.

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на `http://127.0.0.1:8000`. Backend должен быть запущен отдельно; единый запуск описывает корневой README после интеграции. Без backend интерфейс показывает ошибку подключения и не подставляет вымышленные ответы.

```sh
npm test
npm run build
```

Сборка проверяет TypeScript и создаёт `frontend/dist`. В production FastAPI должен отдавать `index.html` для `/` и `/cart`, а `/api/cart` — JSON. Конфигурацию backend и секреты клиент не получает.

## Проверяемый сценарий

1. Открыть приложение с работающим backend; дождаться статуса каталога.
2. Ввести существующий артикул. Проверить название, сведения о наличии, характеристики и ссылки на источники/сертификаты.
3. Выбрать количество и нажать «Проверить и добавить». Корзина ещё не меняется.
4. Проверить название, добавляемое и итоговое количество; нажать «Да, добавить N». Только подтверждённый сервером результат изменяет показанную корзину.
5. Открыть `/cart`: там та же корзина сессии. Заказ и оплата на ekt.kz не выполняются.
6. Проверить «Не добавлять»: отмена считается успешной только после ответа `/api/cart/cancel`.
7. Прикрепить синтетический PDF/DOCX/XLSX/XLS/JPEG/PNG до 8 МБ. После успешного чтения отправить вопрос. Legacy DOC предлагает преобразовать в DOCX.

Enter отправляет запрос, Shift+Enter переносит строку. На телефоне корзина открывается в нативном диалоге с возвратом фокуса и закрытием по Escape. Текст запроса, CSRF и вложения не сохраняются в localStorage. В браузере нет секретов или платёжных форм.

## Достоверность и ограничения

- Неизвестные цена/остаток отображаются явно; добавить такой товар нельзя.
- `snapshot` и неполный индекс подписаны. Предупреждения о противоречиях каталога всегда видимы.
- API возвращает данные корзины; optimistic updates отсутствуют.
- `409` блокирует старое предложение до новой проверки. Двойное нажатие не отправляет второй параллельный запрос подтверждения.
- Новое сообщение и серверная отмена инвалидируют предыдущее предложение согласно контракту. Клиент не объявляет серверную отмену при ошибке.
- Текст ответа выводится как обычный текст; ссылки допускают HTTPS без встроенных учётных данных.
- Переписка на экране живёт в памяти вкладки. Сервер сохраняет контекст и корзину в пределах сессии; восстановление визуальной истории после обновления страницы API не предоставляет.
- Реальная корзина ekt.kz не интегрирована: API для неё не предоставлен.

## Проверки текущего этапа

11 автоматических проверок проходят на синтетических ответах в `src/test/`: явное согласие, CSRF/cookie, устаревшее предложение, неизвестные данные, лимит количества, ошибка каталога, вложение, отмена, двойное нажатие, маршрут корзины и небезопасные ссылки. Тестовые товары не импортируются приложением. Production-сборка проходит. Мобильная компоновка и диалог просмотрены в браузере; сквозная проверка с готовым backend выполняется при интеграции и не подменяется этими тестами.

## Сторонние компоненты

React (MIT), Vite (MIT), TypeScript (Apache-2.0), Lucide (ISC); IBM Plex Sans и Manrope (SIL OFL, пакеты Fontsource). Vitest (MIT), Testing Library (MIT), jsdom (MIT), Prettier (MIT) используются при разработке. Точные версии — `package-lock.json`. Значки и шрифты поставляются локально; запросов к Google Fonts нет.

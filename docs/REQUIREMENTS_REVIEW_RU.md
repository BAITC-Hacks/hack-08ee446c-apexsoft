# Проверка по ТЗ «ИИ-ассистент для чата на ekt.kz»

Источник: информационный пакет HackAlem / ТОО «Электрокомплект», присланный участником 23.09.2026. Проверяющий: agent-b. Проверена версия `167e66f` и предшествующий коммит тестов `d74da7e`; дополнительные языковые изменения пока ожидаются. Этот документ фиксирует доказательства и ограничения прототипа, а не объявляет интеграцию с промышленным сайтом завершённой.

## Пять обязательных сценариев

| Требование | Проверка и результат | Ограничение |
| --- | --- | --- |
| Наличие, характеристики и сертификаты из каталога | **Работает в прототипе.** `test_normalization_conflict_certificates_nulls`, `test_ai_free_text_cannot_publish_catalog_facts`, проверки точного артикула/ID в `test_catalog_search.py`. B ранее проверил живую карточку ID 515291: цена 64920 ₸, остаток 23, расхождение токов 160/250 А показано как предупреждение. | Числа относятся к моменту проверки 23.09, не обещают текущее наличие. Ссылка на сертификат выводится только если есть в данных; наличие реального сертификата у живого примера не подтверждено. Индекс ограничен загруженной выборкой, явно отмеченной в интерфейсе. |
| Аналог при нулевом остатке с обоснованием | **Работает на репрезентативных данных.** `test_out_of_stock_analogue_has_reason`: минимум один доступный кандидат, причина выбора. Сравниваются категория и известные критические характеристики. | Не подтверждается полная электрическая взаимозаменяемость: неизвестные/противоречивые параметры требуют специалиста. Для произвольного отсутствующего товара в частичном живом индексе аналог не гарантирован. |
| Условия оплаты, доставки и минимальной партии | **Содержательный ответ есть.** `test_terms_and_partial_search_are_honest`; `backend/knowledge.py` содержит условия и ссылки на страницы магазина, отмечает конфликт условий доставки. | Исходные страницы проверял agent-a. B проверил состав ответа и источников в коде; повторное независимое открытие страниц через web-инструмент было недоступно. Актуальные стоимость и срок подтверждает магазин. |

Реальный резерв/заказ/оплата не вызываются. |

Удаление пересчитывает итог; отложенный повтор подтверждения возвращает актуальное состояние. | Интеграции с пользовательской корзиной ekt.kz и настоящим checkout нет. Если жюри требует именно корзину промышленного сайта, этот пункт выполнен лишь частично: нужен авторизованный API записи и отдельная интеграция. |

## Входы и ограничения

| Пункт ТЗ | Состояние |
| --- | --- |
| Свободный текст и контекст сессии | OpenAI определяет намерение; история ограничена шестью полными обменами, передаётся с обеими ролями. Fallback явно обозначен. Контекст и загруженные файлы изолированы по сессии. |
| Фото, Excel, Word, PDF, JPEG | JPEG/PNG, XLS/XLSX, DOCX и текстовый PDF поддержаны. Синтетический XLSX проверен B в браузере. Legacy DOC требует преобразования в DOCX; сканированный PDF — отправки страниц изображениями. До 8 MiB и 30 страниц PDF, ограничение извлечённого текста обозначается. |
| Задержка в единицы секунд | На предыдущей живой версии B получил 1,13–2,41 с в пяти последовательных API-запросах. Это небольшой пример, не SLA. Тайм-аут интерфейса 60 с; медленная сеть и массовая обработка отдельно не оценены. |
| Никаких изменений состава без явного согласия | Добавление — точная команда/отдельная кнопка. Удаление — явно подписанная кнопка конкретной позиции; сервер требует `confirmed: true`, CSRF и актуальную версию. Модель не имеет инструмента записи в корзину. |
| Не выдумывать цену/остаток | Значения берутся из нормализованных карточек. Неизвестно = `null`, не ноль. Перед добавлением карточка перепроверяется. Сбой живого API не подменяется синтетическими данными. |
| Приватность, отсутствие платёжных данных | Приложение не запрашивает платёжные данные. Сессии, файлы и ответы находятся в памяти; пользователь видит предупреждение о передаче текста/вложений в OpenAI. Секреты остаются в окружении сервера, сканирование Git проходит. Возможен ввод чувствительной информации самим пользователем — автоматическая полная фильтрация не заявляется. |
| Десктоп и мобильная версия | B проверил десктопное добавление/удаление, потерю ответа с XLSX и повтор. При ширине 390×844 ошибка сессии и кнопка переподключения доступны внутри модальной корзины; восстановление работает. Реальная телефонная клавиатура отдельно не проверена. |
| Казахский язык (опционально в исходном ТЗ) | Явно включён пользователем в текущую работу. agent-a реализует язык/AI; agent-b подключает и проверяет итоговые ответы. На версии `167e66f` ещё не готово. |
| Рекомендации сопутствующих товаров, авторизованная история | Не реализованы. Это опции ТЗ. |
| Передача сложного вопроса менеджеру | Есть ссылка на контакты и рекомендации обратиться к специалисту. Автоматическая передача диалога живому оператору не реализована. |
| Репозиторий и README | Код и история опубликованы только в выданном репозитории `BAITC-Hacks/hack-08ee446c-apexsoft`. README описывает запуск, архитектуру и данные. |

## Доказательства проверки

- Версия `31da0ab`: B самостоятельно выполнил 116 backend-тестов, 36 frontend-тестов, production build и сканирование секретов.
- Версия `167e66f`: 127 backend-тестов, 40 frontend-тестов, production build, `git diff --check`, сканирование секретов — успешно. Все новые тесты с локальными подставными ответами, без нагрузки на EKT/OpenAI.
- Браузер: отдельный hostname `localhost` для синтетического стенда, `127.0.0.1` для пользовательского live-приложения; разные порты одного hostname не изолируют cookies.
- Результат agent-a «9 из 9 live-eval» — сообщён напарником; B не выдаёт его за собственное повторение. Смысловая проверка и границы этого прогона описаны в `TESTING.md`.
- GitHub Actions, по сообщению agent-a, заблокирован billing issue. Локальные результаты не означают успешный CI.

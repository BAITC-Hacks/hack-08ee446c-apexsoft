# Развёртывание EKT-консультанта

Инструкция для человека, получившего репозиторий. Самый прямой путь — один контейнер со всем приложением. Код frontend собирается заранее, FastAPI отдаёт его и API по одному домену.

**Проверено локально:** Python-сервер, тесты, сборка frontend. **Не подтверждено:** сборка нового Docker-образа и живое размещение в облаке. После первого деплоя выполните проверку ниже.

## Railway: всё приложение в одном сервисе

1. Импортируйте репозиторий в Railway. Для приватного репозитория выдайте Railway доступ к нему. Выберите ветку main, корневую папку репозитория.
2. Railway должен обнаружить корневой Dockerfile. Он собирает frontend в Node.js и переносит результат в Python-образ. Не указывайте frontend как корневую папку этого сервиса.
3. В Variables сервиса задайте EKT_API_USERNAME, EKT_API_PASSWORD, OPENAI_API_KEY. Не записывайте реальные значения в репозиторий.
4. Задайте HOST=0.0.0.0, EKT_SECURE_COOKIE=true, при необходимости OPENAI_MODEL=gpt-4.1-mini. PORT оставьте платформе: scripts/run.py читает его автоматически.
5. Используйте один процесс и одну реплику. Команда запуска уже задана в образе: python scripts/run.py. Не добавляйте --reload или --prompt-secrets.
6. Включите публичный HTTPS-домен. Healthcheck: /api/health (также указан в railway.toml).
7. Дождитесь готовности сервиса и загрузки индекса, затем выполните проверку ниже.

Сессии, корзины и индекс хранятся в RAM. Перезапуск/новый деплой сбрасывает серверные данные. Подключение дискового volume само по себе это не исправляет: потребуется изменение приложения на общее хранилище.

Документация платформы: [контейнерные сервисы](https://docs.railway.com/services), [деплой Docker-проекта](https://docs.railway.com/guides/docker-compose).

## Docker на VPS или другом контейнерном хостинге

Из корня репозитория:

```sh
docker build -t ekt-assistant .
docker run --rm --name ekt-assistant -p 8000:8000 ekt-assistant
```

Это демонстрационный запуск без ключей. Для живого режима сначала настройте EKT_API_USERNAME, EKT_API_PASSWORD и OPENAI_API_KEY в окружении своего терминала безопасным способом. Docker возьмёт значения из этого окружения:

```sh
docker run --rm --name ekt-assistant -p 8000:8000 -e EKT_API_USERNAME -e EKT_API_PASSWORD -e OPENAI_API_KEY ekt-assistant
```

Локальный адрес: http://127.0.0.1:8000. Для публичной установки поставьте HTTPS-прокси перед контейнером и передайте -e EKT_SECURE_COOKIE=true. Проксируйте весь сайт, сохраняйте Cookie/Set-Cookie и X-CSRF-Token; разрешите запросы не менее 9 MiB для файла до 8 MiB плюс multipart. Не кешируйте /api/*.

На Linux без Docker: установите Python 3.12 и Node.js 22.12+, создайте venv, установите requirements.lock, выполните npm --prefix frontend ci и npm --prefix frontend run build, затем запускайте .venv/bin/python scripts/run.py с HOST=0.0.0.0 и нужным PORT. Настройте автозапуск системным менеджером процессов. Только один экземпляр приложения.

## Vercel: frontend + отдельный backend

Vercel поддерживает FastAPI, включая lifespan. Но наш текущий backend хранит сессии/корзины в памяти процесса и индексирует каталог в фоне. Перенос целиком в масштабируемые Functions без адаптации не обеспечивает целостность этих данных. Для такого варианта сначала нужны общее хранилище, отдельный индексатор и проверка ограничений загрузки файлов. [FastAPI на Vercel](https://vercel.com/docs/frameworks/backend/fastapi).

Практический вариант для текущего кода:

1. Разверните backend по инструкции Railway выше и получите его HTTPS-домен.
2. Создайте второй проект Vercel из того же репозитория. Root Directory: frontend; Framework: Vite; Install: npm ci; Build: npm run build; Output: dist.
3. Создайте frontend/vercel.json по примеру ниже, заменив YOUR-BACKEND.example на настоящий домен. Этот адрес не является секретом. Ключи OpenAI/EKT остаются только на backend.
4. Выполните деплой. Запросы браузера идут на /api того же домена Vercel, а rewrite проксирует их на сервер. Отдельный CORS-доступ в приложении для такой схемы не нужен.
5. Проверьте cookie, CSRF, вложения, корзину и прямое открытие /cart. Эта конкретная схема в облаке ещё не проверена.

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://YOUR-BACKEND.example/api/:path*" },
    { "source": "/cart", "destination": "/index.html" }
  ],
  "headers": [
    {
      "source": "/api/:path*",
      "headers": [
        { "key": "Cache-Control", "value": "no-store" },
        { "key": "x-vercel-enable-rewrite-caching", "value": "0" }
      ]
    }
  ]
}
```

Порядок правил важен: /api сохраняет свой префикс на backend. Не заменяйте все запросы на index.html — иначе API перестанет работать. Не кешируйте сессии/корзины на CDN. Аналогичная схема применяется к другим статическим хостингам с обратным прокси. [Официальная инструкция rewrites](https://vercel.com/docs/routing/rewrites).

Если вместо внешнего backend использовать Vercel Functions, отдельно учитывайте лимиты их запросов/ответов: заявленные приложением 8 MiB вложений могут превышать допустимый размер платформы. [Лимиты Functions](https://vercel.com/docs/functions/limitations). Не обещайте поддержку всех вложений без проверки конечного маршрута.

## Проверка после каждого деплоя

- Главная страница и /cart открываются; /assets/* возвращает JS/CSS, а не HTML.
- /api/health возвращает JSON. Режимы catalog=live и ai=openai говорят о настройке; доступ к сервисам подтвердите реальным запросом.
- Для полного поиска дождитесь index_complete=true; количество indexed_products зависит от каталога. Во время индексации отсутствие результата не означает отсутствие товара в магазине.
- Найдите известный артикул, проверьте фото, цену и наличие; прикрепите JPEG и небольшой PDF/Excel/Word.
- До подтверждения корзина не меняется. После подтверждения и перехода на /cart виден выбранный состав. В другом браузере корзина отдельная.
- Обновление страницы сохраняет видимую переписку. После перезапуска сервера ожидается новая серверная сессия.
- В браузере нет API-ключей; запросы к API не кешируются; публичный сайт работает по HTTPS.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Платформа не видит порт | HOST=0.0.0.0, PORT из окружения, один процесс |
| API работает, интерфейс/стили отсутствуют | frontend/dist должен быть собран **до старта** Python |
| Показываются синтетические товары | Обе переменные EKT заданы серверу |
| Фото не распознаётся | OPENAI_API_KEY, поддержка изображений моделью, доступ к внешнему API |
| Корзина пропадает между запросами | Несколько процессов/реплик либо перезапуск; требуется один экземпляр |
| Ошибка сессии в браузере | HTTPS, Secure cookie, передача Cookie/Set-Cookie и CSRF через прокси |
| Большой файл получает 413 | Лимит приложения 8 MiB и лимиты прокси/платформы |
| После старта найдено мало товаров | Индекс ещё загружается либо EKT недоступен; проверьте health и реальный запрос |

Публичное размещение не превращает демо-корзину в настоящую корзину ekt.kz. Недостающий партнёрский контракт описан в README.

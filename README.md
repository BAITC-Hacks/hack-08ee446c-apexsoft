# ЕКТ — консультант по электротехнике

## 1. Назначение

Веб-прототип консультанта для каталога [ekt.kz](https://ekt.kz/): покупатель задаёт вопрос или прикладывает маркировку/документ, получает карточку товара, проверяет характеристики и наличие, выбирает количество и явно подтверждает добавление.

**Каталог может быть подключён к настоящему API EKT. Корзина всегда демонстрационная:** приложение не меняет корзину ekt.kz, не резервирует товары и не оформляет заказ. API корзины магазина в предоставленном доступе отсутствует. Этот статус виден в интерфейсе и ответах API.

## 2. Архитектура

```text
Браузер: React + TypeScript
  └─ FastAPI, один origin, сессионная cookie и CSRF
       ├─ OpenAI Responses API → намерение и поисковый запрос
       ├─ адаптер EKT → каталог, карточки, цена, остатки
       ├─ подбор кандидатов на замену по данным каталога
       ├─ чтение вложений → текст/изображение в памяти сессии
       └─ предложение → явное подтверждение → повторная проверка → демо-корзина
```

Модель не выполняет изменение корзины и не является источником цен/остатков. Сервер формирует эти сведения из каталога. `/cart` открывает текущее состояние корзины сессии; `/api/cart` возвращает JSON. [Контракт API](docs/API_CONTRACT.md) и [параметры интерфейса](DESIGN.md) описывают реализацию.

## 3. Возможности

- Поиск по артикулу, ID и свободному запросу; характеристики, складские остатки и сертификаты, когда ссылки есть в API.
- Подбор без артикула: уточнение назначения и недостающих параметров с учётом последних шести пар сообщений. Модель выбирает вопросы из ограниченного набора; сервер не публикует свободные выдуманные характеристики и не назначает сечение или номинал по догадке.
- Кандидаты на замену отсутствующей позиции с объяснением совпадений. При противоречии характеристик исходной позиции автоматический подбор блокируется.
- Ответы об оплате, доставке, самовывозе и минимальной партии со ссылками на официальные страницы. Противоречащие друг другу условия сайта показываются явно.
- Предложение количества, отдельные подтверждение и отмена, проверка суммарного количества, кратности и свежей цены/остатка. Повтор того же подтверждения не добавляет товар повторно.
- Адаптивный интерфейс, клавиатурная навигация, вложения, сообщение об обработке данных OpenAI.

## 4. Технологии и структура

`backend/` — FastAPI, адаптер каталога, OpenAI, вложения, правила корзины. `frontend/` — React/Vite/TypeScript. `tests/` и `frontend/src/test/` — автоматические проверки. `scripts/run.py` — запуск и скрытый ввод секретов; `scripts/check_secrets.py` — проверка известных форматов токенов перед публикацией.

Python-зависимости зафиксированы в `requirements.lock`, npm-зависимости — в `frontend/package-lock.json`. База данных для локального прототипа не нужна: сессии, контекст, корзины и вложения хранятся в оперативной памяти.

## 5. Системные требования

Python 3.10+; проверено на Python 3.12.14 под Windows. Node.js 22.12+; сборка проверена на Node.js 24.19.0. Нужны Git, npm и свободный локальный порт 8000. Для живого режима серверу требуется HTTPS-доступ к `ekt.kz` и `api.openai.com`. GPU не требуется.

## 6. Установка

Клонируйте основную ветку репозитория и перейдите в каталог проекта:

```sh
git clone https://github.com/BAITC-Hacks/hack-08ee446c-apexsoft.git
cd hack-08ee446c-apexsoft
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
```

Linux/macOS:

```sh
.venv/bin/python -m pip install -r requirements.lock
```

Сборка интерфейса одинакова для всех систем:

```sh
cd frontend
npm ci
npm run build
cd ..
```

## 7. Настройка

| Переменная серверного процесса | Значение и назначение |
| --- | --- |
| `EKT_API_USERNAME`, `EKT_API_PASSWORD` | BasicAuth для каталога. Без полной пары включаются синтетические товары. |
| `OPENAI_API_KEY` | Ключ OpenAI. Без него доступен ограниченный поиск по тексту/артикулу; распознавание фото и понимание документов не работают. |
| `OPENAI_MODEL` | По умолчанию `gpt-4.1-mini`; модель должна поддерживать Responses API, строгий JSON и изображения. |
| `EKT_INDEX_PAGES` | По умолчанию 100, допустимо 1–1000. Число загружаемых страниц каталога. |
| `HOST`, `PORT` | По умолчанию `127.0.0.1` и `8000`. |
| `EKT_SECURE_COOKIE` | `false` для локального HTTP; для развёртывания за HTTPS установить `true`. |

`.env.example` показывает только имена и несекретные значения. **Файл `.env` автоматически не загружается.** Передавайте настройки окружением процесса либо используйте скрытый интерактивный ввод ниже. Не вставляйте ключи в frontend, Git, команды с аргументами, логи или общие документы.

## 8. Запуск

Демонстрационный режим без внешних ключей, Windows:

```powershell
.\.venv\Scripts\python.exe scripts/run.py
```

Живой каталог и OpenAI, Windows:

```powershell
.\.venv\Scripts\python.exe scripts/run.py --prompt-secrets
```

Введите выданный логин EKT, пароль и ключ OpenAI в приглашениях терминала. Пароль и ключ не отображаются и не записываются в файл. На Linux/macOS замените путь Python на `.venv/bin/python`. Настроенные через окружение секреты используются без `--prompt-secrets`.

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Состояние процесса: `/api/health`; документация методов: `/docs`. Поля интеграций в health показывают режим настройки; успешный health сам по себе не подтверждает доступность внешних сервисов — это проверяется запросом товара.

`--reload` включает перезапуск при изменении Python-файлов только для разработки. Каждый перезапуск очищает сессии и заново загружает индекс. Для отдельной разработки frontend запустите `npm run dev` из `frontend/`: Vite на порту 5173 проксирует `/api` на порт 8000.

## 9. Проверка основного сценария

В режиме без ключей используются **синтетические позиции**, явно подписанные в интерфейсе:

1. Напишите `900001`. Ожидается товар без остатка и доступный аналог `900002` с объяснением.
2. В карточке `900002` укажите 2 и нажмите «Проверить и добавить». Корзина остаётся пустой.
3. Нажмите «Не добавлять». Корзина остаётся пустой, предложение аннулируется.
4. Повторите предложение и нажмите «Да, добавить 2». Ожидается 2 × 1 200 = 2 400 ₸ в **демонстрационной** корзине.
5. Откройте ссылку на корзину: состав тот же. Попытка добавить ещё 11 при остатке 12 должна блокироваться.
6. У `900003` количество 6 отклоняется: шаг 5. У `900004` добавление недоступно из-за неизвестных цены/остатка.
7. Спросите об оплате и доставке: ответ содержит источники и предупреждение о расхождении условий сайта.

Для живого режима после загрузки выборки попробуйте `200300285_` или ID `515291`. Проверяйте данные текущего ответа: цена и наличие могут изменяться. В проверенной карточке были противоречивые значения тока — приложение показывает предупреждение, а не выбирает одно из них самостоятельно. Отсутствующий сертификат не подменяется вымышленной ссылкой.

При настроенном OpenAI можно прикрепить JPEG с маркировкой или текстовый PDF/DOCX/XLSX и попросить найти указанный артикул. Само чтение вложения не изменяет корзину.

Для проверки диалога последовательно напишите: «Помогите подобрать кабель. Какие параметры нужно указать?», «Кабель для лампы нужен», «У меня нету артикула». Ожидаются вопросы по задаче, пояснение, что артикул не обязателен, и продолжение подбора без изменения корзины. После ответа на вопрос о длине она не должна запрашиваться заново; неизвестные параметры можно уточнить по фото маркировки. При отсутствии OpenAI уточнения ограничены простыми правилами: полноценное понимание продолжения диалога не гарантируется.

Автоматические проверки:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/check_secrets.py
cd frontend
npm test
npm run build
```

Проверены 37 серверных и 13 клиентских тестов. Они используют синтетические ответы и не требуют платных API. Диалог проверяется отдельно с живым OpenAI: тесты с подставными намерениями модели подтверждают серверные границы, но не качество её решений. Отдельно проведены живые проверки OpenAI + EKT, чтения DOCX/XLSX/текстового PDF, распознавания JPEG, поиска по XLSX и подтверждения демо-корзины. Это не доказательство подключения корзины реального магазина.

## 10. Данные, пределы и ограничения

- Живые источники: `GET https://ekt.kz/api/products?page=N` и `GET https://ekt.kz/api/products/detail?id=ID`. По умолчанию загружается репрезентативная выборка, при проверке — 2 000 товаров. Число карточек не означает полноту каталога. Отсутствие в поиске не означает отсутствие товара в магазине.
- `backend/data/catalog_snapshot.json` содержит только специально созданные синтетические товары. В живом режиме они не загружаются. Цены/остатки не записываются в постоянный кэш; карточки поиска могут кэшироваться в памяти до 30 секунд. Перед предложением и подтверждением выполняется свежий запрос.
- Аналоги — кандидаты по категории, названию и доступным ключевым параметрам; полнота технической совместимости не гарантируется. Окончательный выбор оборудования требует проверки характеристик.
- JPEG/PNG: до 8 MiB, уменьшение до 1600×1600 и удаление метаданных. PDF: текстовый слой, до 30 страниц, без пароля; полностью сканированные PDF нужно преобразовать в JPEG/PNG. DOCX: абзацы и таблицы. Старый DOC не поддерживается.
- XLSX/XLS: первые 5 листов, до 500 строк и 20 столбцов. Формулы не пересчитываются, читаются сохранённые значения. Максимум 16 000 символов извлечённого текста, 4 вложения на сообщение и 8 на сессию. CSV не поддерживается.
- Обрабатывается одна выбранная позиция за раз. Автоматическое построчное сопоставление всей спецификации и пакетное добавление ещё не реализованы. При отключённом/недоступном OpenAI содержимое документов не используется для поиска.
- OpenAI получает запрос, ограниченный контекст и выбранные вложения с `store:false`. Не прикладывайте платёжные данные, персональные документы или конфиденциальные сведения. `store:false` не является обещанием отсутствия любой обработки/хранения на стороне провайдера.
- Cookie действует до 2 часов с выдачи через `/api/session`; обычные сообщения её срок не продлевают. Сервер удаляет сессию после 2 часов бездействия при очередном обращении к сессиям; предложение истекает через 5 минут. Контекст, файлы и корзина теряются при перезапуске; визуальная история чата не восстанавливается после обновления вкладки. Ограничения: 500 сессий и 30 POST-запросов в минуту на сессию.
- В живых одиночных прогонах получены 3,78 с для текстового запроса, 2,53 с для JPEG и 1,21 с для таблицы. Первый прогон во время загрузки индекса занял 15,64 с. Это замеры, не SLA: время зависит от сети, OpenAI, каталога и числа проверяемых аналогов. Фоновая индексация оставляет часть соединений пользовательским запросам.
- Прототип запускается одним серверным процессом. Многопроцессный production, общий Redis/БД, полная индексация, установка на ekt.kz, публичный хостинг и реальная корзина требуют отдельной интеграции. Для публикации нужны HTTPS, серверное управление секретами и защита API от внешнего злоупотребления.

## 11. Сторонние компоненты

Существующие библиотеки устанавливаются пакетными менеджерами; версии закреплены в lock-файлах. FastAPI (MIT), Uvicorn и HTTPX (BSD-3-Clause), python-multipart (Apache-2.0), pypdf (BSD-3-Clause), openpyxl и python-docx (MIT), Pillow (MIT-CMU), xlrd (BSD), pytest (MIT). На клиенте: React/Vite/Vitest/Testing Library/jsdom/Prettier (MIT), TypeScript (Apache-2.0), Lucide (ISC); Manrope и IBM Plex Sans через Fontsource (SIL OFL). Шрифты поставляются локально в сборке.

OpenAI Responses API — внешняя служба интерпретации текста и изображений; собственная модель не обучалась. Данные живого каталога и официальных условий принадлежат EKT. Ссылки на источники условий находятся в `backend/knowledge.py` и показываются в ответах. Синтетический набор создан для воспроизводимой проверки и не описывает реальные остатки магазина.
